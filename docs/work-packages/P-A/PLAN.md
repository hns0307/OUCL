## 独立环境和执行顺序

1. 分配本包独占 `docs/work-packages/P-A/runs/<时间戳>-<场景>/`，每次新建，已存在即拒绝。其内`product/OUCL.exe`为上述EXE副本，`OUCL.runtime/profile`及`OUCL.games`均同级全新目录；证据置`evidence/`。检查所有祖先/目标没有重解析点，记录绝对路径、EXE摘要、系统版本、时间与来源设置。此路径只用于测试，不硬编码进产品。
2. 启动前只读检查已有OUCL/Java进程的可识别路径。无法确认窗口/进程归属即停止窗口操作，不结束其他进程。只跟踪本轮启动产生的PID与子进程；同一时刻只运行一个本包游戏，关闭必须由本包明确归属窗口正常退出。不得全局按进程名kill。
3. 先原版全新根、官方源，从EXE界面完成离线档案、版本选择、安装、启动。冷运行时下载和MC冷下载分别记账；任何预置对象/Java/运行时必须标热缓存。失败不在原证据上改PASS，新目录新attempt，并保留前驱。
4. 依次Fabric、Quilt、Forge、NeoForge，各独立产品目录/根。首次无Mod到菜单/退出0，再走资源库精确版本→预览→明确确认→任务终态→Mod列表双检→启动证明Mod加载→退出0。Fabric/Quilt不强求不存在的Mods菜单，以启动日志的loader/Mod版本和菜单截图联合证明；只有文件在mods目录不算加载。
5. 正常退出OUCL，确认本包owner释放；重开同一副本，核对rootId/instanceId/修订/Mod报告和原任务结果，再次启动到菜单并退出0。关闭应用不等于游戏退出，二者分别留证。
6. 网络修复回归先记官方源成功/具体失败；若切换BMCLAPI，另起attempt并记设置，不用镜像成功覆盖官方失败。禁网启动准备与实际无网游戏是不同条目，不能用强制传输拒绝夹具冒充物理离线实机。

逐attempt证据：输入与摘要、开始/结束时间、操作步骤/截图、任务ID/状态、实例与会话ID、实际Java版本、加载器/Mod加载日志、真实退出码、重开结果、错误码及日志定位。私有原始日志留本包证据，公开摘要脱敏路径/身份；不拷玩家日志。截图必须对应本包PID/窗口。断电/中断首轮只保留既有安全阻断结论，不宣称自动恢复；真实故障注入另单列对象/终止点/恢复策略，不破坏正常矩阵。
