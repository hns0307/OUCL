## 1. 决策摘要与边界

推荐第一片仅接受下述自有、固定内容的小型 mrpack，完整完成“原生选择 → 安全预览 → 明确确认 → 新隔离实例 → 就绪提交 → 产品启动及重开”。不是承诺兼容所有 Modrinth 包，也不是开始原地更新。

- 已有原版/加载器/Mod 能力属于既有 G2；P-E 的导入业务、IPC、记录格式和归档 worker 尚未获批。TASK_PLAN 的候选 1E 与 D-13 不被本方案改为 APPROVED。
- 首片 Windows x64，精确 MC/加载器组合；不接 CurseForge、HMCL、纯 `.minecraft`、服务端包、脚本或包内安装器。
- 不增加 provider、签名后台、自动更新、完整玩家 overlay、实例复制、备份或 GC。`DistributionSource` 当前只是契约/纯差异预览，不能用它执行导入，也不能给 mrpack 临时套测试签名来冒充可信源。
- 导入必须创建全新 UUID、私有 gameDir；不能关闭隔离，不能覆盖现有实例、根玩家数据或同名目录。展示名冲突可改名，内部身份不可复用。

## 3. 信任、许可和人工补充

1. 选择器取得本地文件不是信任批准。主进程以无链接普通文件句柄读取，复制到本任务私有暂存、核对复制前后身份与包摘要；预览和确认绑定同一份固定字节。
2. 首个自有样本用随评审冻结的完整包 SHA256 作为带外等价完整性校验。该摘要只认证评审的包字节；不能为任意用户 ZIP 赋予发布者身份，也不替代网络文件的官方来源链。推广任意本地包前另批来源确认政策。
3. 只接官方 Modrinth API 返回的精确版本文件；SHA1、SHA512、长度同时与索引及真实下载匹配，计算本地 SHA256 作为对象身份。沿既有独立来源证明接入对象库，不给任意索引摘要生成可信 `sourceKey`。
4. 网络限首样本所需的官方 Mojang/Forge/Java 及 Modrinth 白名单。包内 URL 不能扩展白名单；拒绝用户信息、非 HTTPS、私网/本机目的地址及未获准跳转。保留既有传输层证书和跳转防护；本片不实现格式支持的其他托管域，遇到就报告不支持。
5. 非法再分发、未知许可、不可确认来源不得自动安装。人工补充只能是用户从合法官方渠道获取的**同一预期文件**：原生选择 → 私有复制 → 双摘要/大小/声明/平台关联复验 → 绑定原 plan/file 身份。不能以“我确认风险”放行摘要不符、来源未证或许可不允许的文件；不能搜索盗链补齐。
6. 首样本无必需人工文件；缺文件时可先取消。人工等待如纳入首片需专门批准 `awaitingInput` 与选择器句柄；否则显示缺失并安全失败，不能声称已支持人工补充产品路径。

## 4. 归档安全与覆盖算法（拟批准限制）

不直接复用 native 解压器写入实例：native、安装器输出验证和 Mod JAR worker 的职责/预算不同。可借用已审查的路径/ZIP 校验逻辑，但新 mrpack 输入/输出协议、预算和测试先批准。首片推荐不新增库；仅在现有校验器经审查能流式复用时实现，否则先停在独立 worker spike，对比维护成本与成熟 ZIP 库的体积、许可、维护/漏洞状态再决策，不安装候选依赖。

| 资源 | P-E 首片候选上限（独立计数） |
| --- | --- |
| mrpack 压缩文件 | 16 MiB |
| ZIP 全部条目 | 1024，包括目录、忽略的服务端条目与非输出条目 |
| 索引 | 1 MiB，严格 UTF-8、拒绝重复 JSON 键和不支持结构 |
| ZIP 总实际展开 | 64 MiB，单项 8 MiB；所有条目累计，包括被后层替换或忽略的条目 |
| 压缩比 | 单项与整体均不超过 100:1；以实际消费/输出计数，零压缩大小的非空异常拒绝 |
| 输出路径 | UTF-8 相对路径最多 240 字节、最多 16 层；Windows 规范化冲突整体拒绝 |
| 索引 files | 首片最多 16 个，总网络内容最多 64 MiB；单个 Mod 仍遵守现有 JAR 64 MiB 限制 |
| worker | 单活动任务，无无限队列；128 MiB heap、120 秒验证硬期限；流块 256 KiB；不能把 heap 当 RSS 上限 |

这些是首片安全预算，非既有产品限额，需批准。最终 RSS/响应/取消时间必须测量；若现有实现必须整包 Buffer，应证明最坏内存满足预算，否则不接入产品，不提高限制掩盖问题。网络环境安装/Java/assets 用既有单独预算，不混入包归档展开限额。

逐条规则：

- 只支持 stored/deflate、单卷、无加密 ZIP；拒绝 ZIP64、不明压缩方式、损坏中央/本地记录、区域重叠、不完整 deflate、CRC/声明长度不符。忽略条目也验证正文并记预算；不在验证过程中执行脚本或 JAR。
- 拒绝 symlink、hardlink/特殊文件类型与 Windows reparse 目标；不沿已有链接读写。拒绝绝对/UNC/设备路径、盘符、反斜线、`.`/`..` 段、NUL、ADS 冒号、保留设备名、尾空格/点、大小写或规范化别名、同层重复及文件/子目录冲突。不 URL 解码或二次解释路径。
- 完整列出后再计算逻辑输出，不按 ZIP 条目顺序边解压边覆盖。首片仅 `config/` 下的两个自有文本（合并为一个最终文件），索引下载只接受固定 `mods/` 文件。其他覆盖域包括 saves、servers.dat、options、日志、账号、启动器元数据、libraries/assets/versions、可执行程序和脚本均拒绝；不是默默丢弃后称完整导入。
- 层顺序：索引文件 → overrides → client-overrides；同层重复拒绝。仅允许两层自有 config 的明确同路径替换，预览列出旧/新摘要与胜出层。任何覆盖 mods 的情况首片拒绝；同路径不同来源不采用最后写入胜出。server-overrides 永不物化到客户端，但仍受全档安全检查与预算约束。
- client unsupported 文件不装；optional 必须显式选择并重算整组计划，缺 env 按格式语义处理。本固定样本将唯一 Mod 明确设 required。未知依赖键、多个加载器、未知格式/枚举或未支持配置整体停在不可确认状态。
- 先在任务专属 workspace 形成完整投影；输出目录祖先/文件句柄重新复验，独占创建/no-clobber。config/Mod 使用私有可写副本，不能把它们软链接到共享对象；运行库继续已有只读共享投影政策。

## 6. 包级生命周期、ready与中断

候选状态为 `selected → validating → preview → accepted → preparing → staging → verifying → committing → ready`；旁路 `awaitingInput`（若批准）、`cancelled`、`failed`、`needsRecovery`。这些是领域状态草案，不直接扩展现有通用 TaskSnapshot 枚举。下载子任务可完成，父任务仍未ready。

1. 预览无实例写入：验证包/许可/环境、整组来源及限制，展示强制隔离、大小与磁盘需求（下载、暂存、副本、运行环境分别估算），选择项和覆盖决策。
2. planId 绑定包摘要、来源版本/摘要、MC/加载器/实测Java要求、选择/覆盖结果、根身份、限制配置版本及生成器版本。预览不是确认，超时不是成功。
3. 确认先持久接受请求，同requestId+同负载只回原任务，异负载拒绝。记录新实例UUID和私有工作域所有权；不能直接调用已有加载器创建并让空环境先公开ready。
4. 准备运行时/下载时只创建非可启动隐藏实例或任务workspace。现有加载器ready提交点需要可审查的“环境完成但包未发布”协调适配；**这是首片必须审批的变化**，不可事后补一个 UI 隐藏标记掩盖已有可启动实例。
5. 验证所有真实JAR/来源、完整平台图与声明集合、config最终摘要、Java事实及文件所有权；缺失/unknown/conflict不允许ready。由共同实例变更许可保护最终复核到发布，游戏/其他写入不得看到半组。
6. 持久日志先记录暂存身份、前后实例记录摘要与阶段，再做私有文件独占物化；fsync内容与必要元数据。最后原子发布带包commitId的实例JSON，作为唯一ready提交点，再持久回执。多文件写入不是跨文件原子事务；安全性靠未发布工作域、日志与启动门禁。
7. ready后重新读取权威记录才能报告成功。若提交已发生但应答丢失，同请求查询返回该结果；不能新建第二实例。

取消：下载/元数据/worker/处理器全部收到信号，等待该任务writer、child close和worker exit后才可报告cancelled。共享物理下载的其他消费者继续；缓存不是失败污染。提交临界区开始后拒绝过晚取消并查询最终结果，不承诺回滚ready实例。人工等待取消不能在迟到选择回执后继续写入。

中断：每阶段重开读原日志/回执与实例JSON，校验包和所有权。ready已提交则复验并返回同实例；明确未提交且无在途writer才能由获准恢复器清理本任务workspace。无法证明拥有权、日志/JSON不一致、未知版本、锁owner未知、外部文件变化一律 needsRecovery并保留材料。首片不自动接管死锁、不删锁、不清扫外部目录。失败后新尝试产生新计划/请求/实例身份；旧任务仍可查询，不重放旧确认。

## 7. 待批准的具体契约与记录设计

以下为评审输入，非已存在 API；实现前仍要提交 TypeScript exact schema 与代码级测试表。

| 接口草案 | 输入/输出与约束 |
| --- | --- |
| `packs:select` | contractVersion1/requestId UUID；原生选择器返回临时 selectionId UUID、包摘要/大小与安全显示名。renderer不得传路径/URL；单sender最多1个，10分钟失效，30秒响应超时（对话框超时需显式定义，不重开选择器） |
| `packs:preview` | selectionId与有限可选文件ID；返回 planRequestId UUID、planId SHA256、ready/conflict/unknown、精确目标与文件/覆盖/许可摘要；35秒受理/预览预算，耗尽不确认，正文≤2 MiB |
| `packs:confirm` | planRequestId、planId、confirmed:true；15秒内接纳并返回原taskId/新实例ID，不等待下载；超时沿同ID查询 |
| `packs:state` | planRequestId，只读返回原计划状态/任务/最终实例或固定错误；3秒；无重放副作用 |
| 任务观察/取消 | 复用既有订阅seq/revision、sender归属、跳号读回/退订；增加pack-import任务种类需严格版本与能力广告；观察退订不取消业务 |
| 人工补充（可延期） | 原task/planId和缺失fileId调用原生选择器，不能传路径；迟到回执、过期/取消/根变化必须拒绝 |

固定候选错误：`PACK_UNSUPPORTED`、`PACK_UNSAFE_ARCHIVE`、`PACK_LIMIT`、`PACK_SOURCE_UNVERIFIED`、`PACK_LICENSE_UNRESOLVED`、`PACK_FILES_CHANGED`、`PACK_PLAN_EXPIRED`、`PACK_ENVIRONMENT_UNKNOWN`；复用已有取消、磁盘、网络、权限、修订冲突和恢复类错误。分类/重试性/本地文案在共享消息表冻结，不返回原始路径或异常堆栈。版本不认识停读停写；仅真实装配能力才广告 packs.v1。

私有记录提案：`pack-plan-<requestUUID>`（不可变计划≤2 MiB）、`pack-import-<taskUUID>`（日志≤1 MiB）、实例可选 `packCommitId`。沿版本化JSON envelope与既有原子日志方向，但data新格式必须批准；记录格式版本、root/task/request/instance、包摘要与许可证据摘要、选择、完整源/目标摘要、覆盖胜出层、环境、阶段及workspace拥有权，禁止凭记录内任意路径恢复。任务请求/回执需要与SQLite接纳原子协调，优先评估现有泛型任务是否足够，不提前声称无表变更。首片旧实例不批量迁移；未知 pack 字段版本不允许新写入，也不丢弃后降级为普通可启动实例。
