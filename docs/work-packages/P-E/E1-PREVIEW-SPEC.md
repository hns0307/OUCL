# E1 安全预览规格与研究验收

2026-11-10，候选设计。对应 [PLAN](PLAN.md) 与 [E0](E0-REPORT-20261110.md)。本轮只在P-E目录验证规则，不装配产品导入器，不新增公开IPC/生产记录/依赖。新增的研究脚本不能直接搬入正式路径。

## 1. 输入与确定性输出

首片精确接受E0样本摘要 `e4cf7d5607a70582cfcec200a381892a83c75e122f5be6bad926de23ff7278f2`。任何不同包先报告不属于已审查样本；恶意变体只用于测试拒绝规则，不因能解析就成为获准产品输入。

预览顺序：原生选择 → 受管私有拷贝/三摘要与身份复核 → 整档归档验证 → 严格索引 → 官方文件元数据绑定 → 完整路径投影/容量预检 → 环境和完整JAR集合验证 → 不可变计划。前一层失败不得继续写入实例；下载前预览缺真实JAR检查时应标 `unknown`，不能显示可确认。可复用E0证据对象仅用于研究，不当成运行时可信缓存。

拟议内部输入字段：`formatVersion:1`、包SHA256及长度、受管选择身份、rootId、固定限制版本、固定来源响应SHA256、选择集（首样本为空）。调用方不提供目标绝对路径或网络地址；reader从自己保有的受管句柄读取。

拟议内部预览输出（所有对象exact，未知字段拒绝）：

| 字段 | 约束/含义 |
| --- | --- |
| formatVersion | 字面量1；不等于公共contractVersion |
| status | `ready` / `conflict` / `unknown`，未知有具体原因，不伪装冲突 |
| archive | SHA256、实际长度、条目数、实际累计展开量、限制版本；无路径 |
| target | MC1.20.1、forge47.4.28、Java17要求、强制隔离；实例身份待确认接纳时创建 |
| files | 逻辑区域/安全相对路径、大小、SHA1/SHA512、来源项目/固定版本/证明摘要；来源URL只留主进程私有记录 |
| overrides | 最终config路径、长度、SHA256、胜出层及被替换层摘要；不返回配置正文 |
| ignored | 仅忽略server层的计数/受控说明，仍验证路径、类型和字节预算 |
| budget | 各独立维度observed/limit/result；未检查明确标notChecked，不用0占位冒充通过 |
| issues | 最多512，固定代码/严重性/可补齐事实；完整正文≤2MiB，超限整体unknown，不截断后ready |
| planId | 对有版本的规范化计划内容计算SHA256；仅内容身份，不是来源信任或确认授权 |

规范化提案：键序固定、字符串原样UTF-8（不做路径修复）、整数十进制、无未定义字段；文件按规范路径排序，issues按固定优先级/路径/代码排序。包身份、最终选择、覆盖结果、来源响应摘要、环境要求、预算版本全纳入计划。公共字段最终schema和规范字节向量需随产品增量批准；本轮研究输出的 `executable:false` 不冒充上述生产计划。

## 2. 层与路径规则的精确化

- 第一片路径仅ASCII。PLAN此前允许规范UTF-8方向过宽，本片推荐收窄为ASCII，先拒绝非ASCII和非NFC，后续支持Unicode再核对Windows文件名等价性；该收窄是候选产品政策，尚未修改正式契约。
- 字节路径与解码后路径均要验证；UTF-8严格解码，拒绝ZIP Unicode path额外字段与中央/本地名称不一致等别名。不得依赖操作系统自动替换非法字符。
- 每层先收集**所有**路径，再查大小写重复、文件/子目录前缀碰撞；禁止读到重名项就覆盖Map。显式目录只作结构，不创建任意输出；目录/文件同名拒绝。
- 首样本只允许固定一个 `mods/ferritecore-6.0.1-forge.jar` 和固定config路径；override中的mods、options、saves、启动参数/脚本一律不支持。原始输入未在允许范围内时，不剔除后声称完整导入。
- 同层重复始终拒绝；跨层只允许基础config被客户端同路径config替换。不能用“最后ZIP条目”选择胜出者。最终config字节应为 `sample=client` 加LF，共14字节，SHA256 `9df1c49a83b3c3caf03c6fbb8abc44dda9d191e0fa01161aacff385174f900c3`。
- 8.3短名、reparse点、硬链接以及路径替换是文件系统事实；仅词法检查无法证明安全，正式物化仍要受管新目录、祖先/句柄检查、文件身份与独占创建。研究脚本不写出归档内容，所以没有证明这些IO条件。
- env可省略时按required评估；本固定样本将client/server显式required。optional、unsupported以及多加载器等输入，研究夹具仅返回不支持；更广泛客户端筛选/可选选择语义仍待具体用例，不对外称完整格式支持。

## 3. 预算、历史与接纳

归档预算沿PLAN：压缩输入16MiB、1024条目、索引1MiB、单项8MiB、展开64MiB、100:1压缩比、最多16索引文件/64MiB下载。目录、server层和被覆盖旧层均计数，不能仅计最终输出。实际流式累计超限立即终止读取，等待worker退出后返回失败；不先完全inflate再检查。

资源历史的准确行为：已有相同下载/在途匹配可在512条时复用；**新**条目在512条拒绝。4个活动jobs的检查更早，不能保证任意满队列场景都能先返回已接纳任务。预览容量只能说明当时情况，确认仍可能被并发请求占用；不能删历史或替换requestId回避限制。513条记录持久解析无效，应保守停写而非当512条截断。

纯图256项目、服务16根、累计读取512、深度32等分别检查。真实图测试采用一根扇出257项目，避免先撞“257根”而假称测到了节点上限；链节点32可通过，33触DEPTH_LIMIT。selected+installed512是输入项数上限，与资源历史512毫无互换关系。

不能把16根分批独立确认后宣称整包可用，也不能因样本只有一根而提高上限。后续增加样本必须重新记录项目数、文件数、声明数、嵌套树、图边/深度、候选读取/搜索预算、元数据/响应体大小及历史余量。

## 4. worker复用判断

已只读检查 `src/services/workers/mod-archive-reader.ts`：现有owner单活动、超时、失败/取消均等待exit，适合借鉴生命周期；其输入是Mod JAR、输出是声明事实，不能把它改成接收任意mrpack目标路径的通用解压器。

推荐专用mrpack验证worker，第一片仅返回有界索引/条目事实及config摘要，不向实例写文件；worker输入路径只能由服务持有，renderer不可提供。128MiB heap与120s提案仍需实际峰值RSS/最坏压缩数据实验，不能由研究脚本耗时推定。成功必须同时收到结构有效回复和正常exit；异常回复、重复终态、消息超限、非零exit均失败；deadline/abort终止并join，不把收到abort等同cancelled落盘。

正式接入前还缺原始ZIP中央/本地记录一致、区域重叠、ZIP64/多卷/加密拒绝、完整deflate消费和所有外部属性的产品实现证据。Python zipfile的部分检查不能替代这些要求。暂无新增依赖理由，本轮没安装库。

## 6. 退出条件与下一片

本轮已交付安全预览字段/拒绝规则与独立规则证据。**E1研究片完成，产品E1仍未实现**。进入正式预览前需要批准专用worker输入/输出/限制和公共preview schema，并协调其他工作包的公共文件所有权；进入确认执行前还需PLAN中的包级ready协调/记录格式批准。不能将“继续”解释成补齐缺失的具体schema决定或绕过父聊天要求的专属目录限制。

推荐下一步将本规格与PLAN §7合并为一次精确评审：只实现固定样本的无写入预览，修改范围限新增core/packs、services/packs、专用worker协议与tests，公共入口装配另列；不把包级确认/执行事务混入。若仍保持当前共享目录约束，可以继续本包内原始ZIP结构攻击向量和独立worker生命周期spike，但不得以此替代正式预览交付。
