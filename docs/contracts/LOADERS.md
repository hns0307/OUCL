# 加载器元数据契约（增量 1）

状态：2026-10-26 已批准实现；本文件只覆盖 Fabric/Quilt 官方元数据进入安装编排前的纯解析边界。

## 信任边界

- 目录和 profile 必须由主进程从加载器官方 HTTPS 端点取得；渲染进程不能提供 URL 或原始 profile。
- profile 只声明版本身份、入口、参数和 Maven 坐标。解析器固定校验加载器、Minecraft 版本、profile ID、客户端入口和允许的仓库来源。
- profile 内同时提供 SHA-1 与大小时，两者作为该官方响应的上游证明保存。缺任一项均拒绝。
- profile 未提供摘要时，安装编排必须从同一官方 Maven 仓库取得对应 `.sha1` sidecar，再创建下载任务。下载后的本地计算摘要只用于复验，不得替代 sidecar 或伪装成上游证明。
- 解析器不选择“最新”版本，不执行参数，不访问网络，也不把未验证组合标记为受支持。

## 有界输入

- 单次目录最多 2048 项，profile 最多 256 个库；参数和规则继续使用版本描述符的既有限制。
- Maven 坐标只允许安全的 group、artifact、version、可选 classifier/extension，并由坐标确定相对路径。
- 当前允许仓库：Fabric `maven.fabricmc.net`；Quilt `maven.quiltmc.org` 与其明确引用的 Fabric Maven。禁止 HTTP、凭据、查询串、片段和任意镜像替换。

Forge/NeoForge 安装器、sidecar 获取、下载任务和实例提交属于后续已批准增量，不由本契约声称已完成。

## 官方目录适配

- Fabric 固定读取 `meta.fabricmc.net/v2/versions/loader/{minecraft}` 与对应的 `/{loader}/profile/json`。
- Quilt 固定读取 `meta.quiltmc.org/v3/versions/loader/{minecraft}` 与对应的 `/{loader}/profile/json`。
- URL 由主进程按受控标识构造，拒绝调用方 URL、重定向、查询串、凭据和非固定 API 版本；响应仍经过既有 2 MiB 上限、超时与严格 UTF-8/JSON 校验。
- 响应 SHA-256 与精确来源 URL 作为“该元数据响应”的来源证据保存；它不替代 profile 所引用 JAR 的上游摘要。

## 公共契约版本

- `loaders.v1` 固定两个方法：按 Minecraft 版本及加载器查询候选，以及创建带加载器的新隔离实例任务。创建请求只含根标识、版本标识、显示名和隔离选项，不接受路径、URL或任意安装器参数。
- 原 `instances.v1` 的原版创建和返回结构保持不变。`instances.v2` 的投影为每个实例明确返回 `vanilla`，或加载器种类及固定版本；不暴露根、任务、文件路径和原始元数据。
- 未完整装配安装事务前不在握手中公布这两个 capability，防止客户端把契约存在误认为功能可用。

## Maven 库下载证明

- profile 内联 SHA-1 与大小的库，以该 profile 响应 SHA-256 作为来源锚；没有内联证明的库，只允许从 profile 已校验的同一官方 Maven URL 读取 `.sha1`。
- `.sha1` 必须是恰好 40 位十六进制（首尾空白可忽略）；库大小由同一 URL 的禁止重定向 HEAD 响应取得，单库上限 1 GiB。SHA-1 或大小不合法时整个计划失败。
- Fabric/Quilt Maven 域名已加入既有下载白名单；实际 JAR 仍必须由共享下载器流式计算并匹配 SHA-1 后才进入对象仓库。sidecar 响应摘要和 profile 响应摘要分别保存，不能相互替代。
- sidecar/HEAD 每项 12 秒超时、并发最多 8；调用方取消会停止尚未完成的证明读取。计划只返回受控相对路径与可信下载规格，不写实例文件。

## Fabric/Quilt 合并版本

- 以已验证的原版描述链为父级，加载器 profile 固定覆盖启动入口并追加其 game/JVM 参数；库按 Maven 的 group/artifact/classifier/extension 身份遵循现有继承覆盖规则。
- 合成后重新运行完整版本解析与安装计划，不直接拼接 classpath 字符串。客户端 JAR、资源索引和原版库继续绑定各自 Mojang 来源；每个加载器库单独绑定 profile 内联证明或该库的 Maven sidecar 证明。
- 安装计划来源统一保存显式算法与摘要，防止把 SHA-256 的加载器响应误记成 Mojang SHA-1。相同内容仍可在对象仓库去重，但独立来源证明全部保留。
- 当前合并层仍是无文件写入的计划阶段；实例记录迁移、下载物化和发布任务完成前，不宣称加载器已安装。

## 实例记录版本

- 实例私有记录新增 `formatVersion: 2` 与加载器身份。原版明确记录 `{ kind: "vanilla" }`；四种加载器必须同时保存固定版本。
- 旧记录缺少这两个字段时只按旧原版格式解析，并在下一次正常的修订号 CAS 写入中原子规范化；读取本身不改磁盘。字段只出现一半、未知版本号或未知加载器均返回恢复错误并停止写入。
- 当前索引继续保持原 v1 摘要，避免破坏旧接口；`instances.v2` 由私有实例记录生成增强投影，后续与加载器安装事务一并装配。

## 安装元数据编排

- Fabric/Quilt 的准备服务并行读取原版官方元数据与精确加载器 profile，随后解析 Maven 证明并合成完整计划；调用方给出的加载器版本不会被“最新版本”替换。
- 返回值同时包含原版版本链/资源索引、原始 profile 字节及响应摘要、逐库下载证明和派生描述符。恢复时必须重新核验原始字节 SHA-256 并重跑解析/合成，不能只信持久化投影。
- 该步骤不创建任务、不下载 JAR、不写实例。只有后续一次安装事务完成全部下载、物化和记录提交后，实例才能变为 ready。

## Fabric/Quilt 安装事务

- 现有安装服务新增固定加载器身份的受理入口；原版入口仍只创建原版。请求摘要包含加载器种类与版本，同一请求标识改变任一字段会按既有幂等规则拒绝。
- `prepared` 检查点保存原版文档、原始加载器 profile 与摘要、官方来源 URL、逐库下载规格及来源锚；读取、重开和启动前均从这些证据重建完整计划。
- 后续下载、对象仓库、文件视图、native、取消收尾和最终 `ready` 提交复用同一事务。加载器库不会走第二套临时下载器；失败/取消实例保持非 ready，共享已验证对象可保留复用。

## 主进程公开边界

- `loaders.v1` 已接入 preload 白名单与主进程 sender/envelope/output 三重校验。查询只接收 Minecraft 版本和四选一加载器标识；创建前主进程重新读取官方目录并确认精确版本仍存在。
- 当前 Fabric/Quilt 使用上述完整安装事务；候选均标记 `unverified`，直到代表矩阵完成真实游戏验收。Forge/NeoForge 返回 `VERSION_UNSUPPORTED`，不会因为契约已列出名称而伪报可安装。
- 创建只返回现有持久任务标识，进度、取消与重连继续复用 `tasks.v1`；渲染进程不能提交 URL、路径、摘要或处理器参数。
