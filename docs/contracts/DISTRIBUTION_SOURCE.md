# 未来分发源契约与测试适配器

本轮仅契约、纯差异预览及内存测试适配器，不装配产品分发源，不连接后台，不开放远程更新。来源解析、玩家确认、下载校验、暂存、提交和恢复最终应复用当前Mod安装流程，不能绕过真实JAR检查/会话锁/修订复核。

`DistributionSource.resolve`以受控packageId/packageVersion请求返回签名信封。payload formatVersion1含包身份/版本、目标MC/Java major/加载器及加载器版本、最多256项文件操作；signature含ed25519/keyId/base64签名。解析器只验证结构，不证明来源可信；真实适配器启用前必须显式配置可信源、公钥/轮换策略并验证规范payload字节，之后仍需文件摘要校验。

清单仅可命名mods/resourcepacks/config三个逻辑区域；拒绝任意根目录、saves、路径穿越、Windows别名/大小写重复和文件/子路径冲突。artifactId是来源内的受控身份，不是任意下载URL。每文件SHA256/大小用于校验；签名覆盖包版本、目标环境及全部有序操作，规范化对象键顺序固定，未知字段/未来格式拒绝。

- add：目标不存在才能新增；未知本地同名内容不会被覆盖。
- replace/remove：同时提供managedId和expectedSha256；预览须对应真实受管登记及当前文件摘要，任一不符整体停止生成可执行变化。
- keep：保留指定文件；清单遗漏的观察文件也保持，绝不把缺项转换为删除。

纯`distributionDiff`最多4096个文件观察，只生成逻辑预览，不读取/写入/删除文件。未来主进程还必须防链接逃逸、重新哈希/检查会话与实例修订、确认签名和目标环境、保护存档/私人配置并复验整笔事务。此预览不能单独授权执行。

测试适配器只在tests/fixtures中：注入临时Ed25519公钥和内存信封，使用Node标准crypto验证，不接HTTP、不持久私钥、不把本地生成摘要当上游信任。产品main没有导入此适配器；无默认公钥或默认相信签名的回退。
